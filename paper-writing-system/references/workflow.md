# 标准作业流程（改稿 / 起草 / 终审）

版本：v1，2026-11-11。任何 agent 接到本体系的论文写作任务，都按本流程逐阶段执行。每个阶段有**必须产出的文件**（闸门）；上一阶段的产出不齐，不进入下一阶段。所有过程文件放在工作目录 `work/` 下，并在 `work/RUNLOG.md` 逐阶段登记（模板见 `templates/RUNLOG.md`）。

适用场景：用户给出一篇文章的实证部分（表格、结果、代码或复现包）和一些文字内容（可能是他描述的研究故事，也可能是待修改的初稿），要求用本技能修改或起草。

```
阶段 0 接收与分诊 → 阶段 1 一次性询问 → 阶段 2 事实底稿 → 阶段 3 诊断与方案
   → 阶段 4 逐章修改/起草 → 阶段 5 语言终审 → 阶段 6 一致性检查 → 阶段 7 Word 排版 → 阶段 8 交付
```

## 阶段 0　接收与分诊（不问用户，自己判断）

1. 读 `SKILL.md`、`protocol.md`、本文件。
2. 清点输入，逐项登记到 RUNLOG：
   - **实证材料**：表格（docx/xlsx/tex/csv）、回归日志、复现包、图；
   - **文字材料**：判断属于哪一类：
     - (a) **初稿**：有完整章节结构的成文稿件；
     - (b) **故事**：作者对研究问题、机制、发现的口头或笔记式描述；
     - (c) **混合**：部分章节已成文，部分只有要点；
   - **其他**：导师意见、审稿意见、目标期刊、范文、已有判例。
3. 判定任务类型：改稿（a）/ 起草（b）/ 补写加改稿（c）/ 只做终审 / 只去 AI 味 / 审稿回复。
4. **产出**：`work/RUNLOG.md` 的"输入清单"与"任务类型"两栏。

## 阶段 1　一次性询问（只问用户才能回答的，集中一次问完）

用 `templates/intake.md` 的问题清单，删去已能从材料中确定的项，剩下的**一次问完**。有提问工具时用提问工具，每题给 2–4 个选项、标出推荐项和默认值（protocol D10 设问原则），不提空白问答题。

必问（材料里确定不了时）：
1. **写作模式**：E 英文稿 / ZE 先中文后译英投英文刊 / ZC 投中文期刊（决定人称、篇幅、结论结构，见 `structure.md` §0）。
2. **目标期刊**（决定摘要字数、排版档案）。
3. **授权级别**：只批注 / 可以直接改 / 改后由作者逐条确认。
4. **事实来源**：数字以哪份表或日志为准；表与正文冲突时以谁为准。
5. **已裁决、不许动的内容**：措辞、结构、导师已认可的段落。
6. **是否交导师审阅**（决定【导师】条目是否优先）。

可选（有默认值，不问也行）：篇幅上限、截止时间、排版档案（默认 `cn-workingpaper`）、是否需要英文译稿。

**无人应答时**（定时任务或用户离开）：按默认值执行，在交付报告第一行写明采用了哪些默认值；授权级别默认"只批注"。

**产出**：`work/intake.md`（问题、回答、采用的默认值）。

## 阶段 2　事实底稿（先把数字和事实固定下来，再动文字）

1. 从实证材料抽取全部估计结果，填入 `work/facts.csv`（模板 `templates/facts.csv`）：表号、列、变量、系数、标准误或 t 值、显著性、观测数、因变量均值、经济显著性换算值。
2. 从文字材料与表格抽取样本事实：样本期、样本量、批次数、数据来源、变量定义。
3. 建立术语表 `work/terms.md`（模板 `templates/terms.md`，每行"标准名 | 需统一掉的别名"）：每个对象只取一个名字，ZE 模式附英文译名（见 `language/zh.md` §F）。
4. 列出论证要点 `work/claims.md`：研究问题、核心机制、每个结果对应的论断；标注哪些来自作者、哪些需要作者确认。
5. 材料不足的地方列入缺口清单，不编造（protocol D2、D3）。

**产出**：`work/facts.csv`、`work/terms.md`、`work/claims.md`、缺口清单（写入 RUNLOG）。

## 阶段 3　诊断与方案

1. 按 `structure.md` 判定框架原型，列出全文骨架（章节序、每章功能段、篇幅预算）；按 `narrative.md` 列优势清单（每条绑表列或检验）、定主战场、记下主动放弃的比较维度。
2. **初稿或混合稿**：逐章对照 `sections/` 各文件的段落地图与自查清单，写批注，分级：
   - P0：事实错误、论证矛盾、缺功能位；
   - P1：结构与顺序问题、规则违反；
   - P2：语言与表述问题。

   每条写明位置、原文整句、问题、依据（文件与条号）、**拟改文**（可直接替换的完整句子），写入 `work/decisions.md`（模板 `templates/decisions.md`）。
3. **故事稿**：按骨架给出每章的段落计划，每段注明内容来源（facts / claims / 待作者补）。
4. **闸门**：按 protocol D10 逐条设问，作者对每条选 同意 / 拒绝 / 自填，结果登记到 `work/decisions.md`。授权级别为"只批注"的，到此交付批注与裁决清单，流程结束。"可以直接改"的，把方案和 P0 清单发给作者确认后再进入阶段 4；作者无应答时，只执行 P0 与 P1 中不涉及作者裁决的项。

**产出**：`work/diagnosis.md`（骨架、批注或段落计划、待作者裁决项）。

## 阶段 4　逐章修改或起草

**顺序**：先实证、后前端（导师 A40）：

数据与变量 → 识别 → 结果 → 稳健性 → 机制与异质性 → 理论与假设 → 背景与文献 → 引言 → 结论 → 摘要 → 表图与脚注

每一章固定四步：
1. 加载对应的 `sections/` 文件与语言文件（ZE、ZC 用 `language/zh.md`，E 用 `language/en.md`）。
2. 在原稿上增量修改（D4）；起草时只用 facts、claims 与作者材料。
3. 跑该章文件末尾的自查清单。
4. 在 `work/changes.md` 登记每处改动：位置、改前、改后、依据条号。

改稿时用 `scripts/docx_tools.py` 在 docx 上做最小替换，保留原格式；不要整段重建。

**产出**：修改后的稿件（新文件名，原稿不动）、`work/changes.md`。

## 阶段 5　语言终审（先检测、后报告、再改）

1. 运行 `python scripts/run_checks.py <稿件.docx> --mode ZE|ZC|E --terms work/terms.md --facts work/facts.csv`，得到 `work/check-report.md`。
2. 按 `language/ai-tone.md` 的分级处理命中项：
   - A 级（机械改，如解释性冒号）与 B 级：都按 protocol D10 逐条列出原文与拟改文，由作者逐条选 同意 / 拒绝 / 自填；A 级可先问"是否全部按建议"，作者同意才批量执行；
   - 只落笔作者同意或自填的条目，登记到 changes；
   - C、H 级：只报告；X 级：不改。
3. 改完复跑检查脚本，确认命中数下降、数字零改动。

**产出**：`work/check-report.md`（改前、改后两版）。

## 阶段 6　一致性检查（交付前必做）

逐项完成，结果写入 check-report：
1. **数字**：全文效应数字与 facts.csv 一致；小数位统一；百分点与百分比不混（`sections/results.md` §6）。
2. **交叉引用**：节号、表号、图号、附表号都存在；路线图与正文一致（`structure.md` §5.4）。
3. **术语**：terms.md 中每个对象全文只用一个名字。
4. **机制解释**：引言、理论、实证、结论对同一结果的解释一致（判例 C-12）。
5. **参考文献**：正文引用与文末列表逐条互查（判例 C-24）。
6. **主结果在场**：摘要（可选）、引言、结论中的主结果与正文一致（判例 C-20）。

前三项与第 5 项由 `run_checks.py` 自动完成，第 4、6 项人工完成。

## 阶段 7　Word 排版

用 Word 排版插件（`plugins/word-layout/`）：
1. `python plugins/word-layout/docx_format.py check <稿件.docx> --profile <档案>`：只报告偏差。
2. 确认后 `apply`：输出新文件，原文件不动。
3. 打开或渲染成 PDF 抽查：标题层级、正文、表格（三线表）、图题、脚注、参考文献。

档案见 `plugins/word-layout/profiles/`。默认 `cn-workingpaper`，即 示例稿交导师版的格式。

**产出**：排版后的 docx（必要时附 PDF）。

## 阶段 8　交付

交付物固定为四件：
1. **修改稿**：docx，文件名带日期与版本号，原稿不动；写回用户本地前按 D8 检查修改时间，并提醒作者关闭文件。
2. **修订说明**：`work/changes.md` 整理成 `templates/revision-notes.md` 的格式，内容包括：
   - 做了什么、依据哪条；
   - 没做的项及理由；
   - 采用的默认值。
3. **检查报告**：`work/check-report.md`（数字、交叉引用、术语、语言命中、排版偏差）。
4. **待作者裁决清单**：B 级语言项、P0 中需要作者决定的项、缺口清单。

回复用户时写一段简短说明：改了什么、还剩什么要他定，以及文件位置。不在回复里复述全部修改。

## RUNLOG 登记规则

每完成一个阶段，在 `work/RUNLOG.md` 追加一行：阶段、完成时间、产出文件、未完成项。用户或另一个 agent 接手时，从 RUNLOG 最后一行继续。
