# 论文写作规则体系：总纲与使用协议

版本：v5.4，2026-11-13（v1 建于 2026-10-23）。**这是整个体系的唯一入口。** 任何 agent 接手本体系的论文写作类任务（中文或英文），先读本文件，按任务路由加载对应文件，再开工。本文件中的路径均相对于 `references/`。

## 1. 体系分层与文件地图

体系按"写到哪里查哪里"分层，来源作为每条规则的标注，不单独成层。

| 层 | 文件 | 管什么 |
|---|---|---|
| 总纲 | protocol.md | 任务路由、工作纪律、工作方法、失效模式、待裁决张力 |
| 流程 | workflow.md（裁决清单模板 templates/decisions.md） | **标准作业流程**：阶段 0 接收分诊 → 1 一次性询问 → 2 事实底稿 → 3 诊断方案 → 4 逐章修改 → 5 语言终审 → 6 一致性检查 → 7 Word 排版 → 8 交付；每阶段的必需产出与闸门 |
| 工具 | ../scripts/run_checks.py、../scripts/docx_tools.py、../plugins/word-layout/、../templates/ | 自动检查（红线、冒号、节首节末、长句、人称、术语、交叉引用、数字、参考文献）；docx 读取与最小替换；Word 排版插件；开工信息表、事实底稿、RUNLOG、修订说明模板 |
| 结构层 | structure.md | 写作模式（E/ZE/ZC）、总原则、框架选型、篇幅预算、跨章共性、**章节间衔接与交叉引用（§5）**、逻辑连词（§5.5）、防御性写作与限定（§6） |
| 叙事层 | narrative.md | 主战场与优势选择、优势如何明说、比较范围、不利信息的摆位（正文/脚注/不写）、必报红线、材料不理想时的取舍顺序 |
| 章节层 | sections/abstract.md、introduction.md（附 introduction-en-card.md）、background-literature.md、theory-hypotheses.md、data-variables.md、identification.md、results.md、robustness.md、mechanism-heterogeneity.md、conclusion.md、tables-figures-footnotes.md | 每章的篇幅、段落地图、写法规则、中英常用句式、常见问题、自查；results.md 同时管全稿的结果报告与数字纪律 |
| 语言层 | language/zh.md、language/en.md、language/ai-tone.md | 跨章节通用的语言规则：证据强度、人称与主体、路标与收束、句长、一物一名、句式红线、段落纪律；去 AI 味的检测与改写 |

**来源标注**：结构层、章节层、语言层的每条规则后标【导师 Ax】【语料】【22 篇】【判例 C-xx】【规则】。技能包之外的原始材料在技能文件夹 `source_materials/`（英文引言填空手册、句式库、版式证据、AI 痕迹清单等）；10 月的旧实验在 `_archive_2026-10/`，不再作为规则来源。

## 2. 优先级

1. **协作纪律**（sources/source-layer.md：批注不代改、先想后写、事实与声音归作者）与本协议第 4 节工作纪律：任何任务不可违反。
2. **本体系的裁决**：判例库与各文件中标【规则】的条目，以及 language/zh.md §I 句式红线。
3. **带【导师】标注的条目**：交导师审阅或导师共同作者的稿件，优先于语料统计与风格插件。
4. **结构层、章节层、语言层的其余条目**（依据语料与判例）。
5. **风格插件**：加载后在文体上优先于第 4 级，但不得违反第 1—3 级。

同一文件内冲突按"禁令 > 义务 > 预算"仲裁；篇幅缩放只压缩散文，不删整节功能位。跨文件张力见第 7 节，只报告、不自裁。

## 3. 任务路由

改稿、起草、补写、终审类任务一律按 `workflow.md` 的阶段执行；下表说明各任务在流程中走到哪一步、加载哪些文件。

| 任务 | 加载顺序 | 产出 |
|---|---|---|
| 批注（默认） | workflow.md 阶段 0—3（到阶段 3 交付批注）| 批注文件：只批注不改原文，分级 P0/P1/P2，每条注明依据文件与条号 |
| 逐节审读 | 同上，逐章对照 sections/ 的段落地图与自查清单 | 审读报告：共性问题、逐节问题、合规项（好段落标"勿动"） |
| 改稿（须明确授权） | workflow.md 阶段 0—8 全程 | 新版本 docx（原稿不动）＋修订说明＋数字零改动校验；未做项注明理由 |
| 结构设计 / 新稿骨架 | structure.md §0—§4 → sections/ 各章的篇幅与段落地图 | 骨架方案：模式、框架原型、章节序、每章功能段、篇幅预算 |
| 章节起草（须有事实包） | workflow.md 阶段 0—8（阶段 3 产出段落计划）；对应 sections/ 文件（英文引言加 introduction-en-card.md）→ language/ | 草稿＋输入使用报告与缺口清单（D3） |
| 语言终审（定稿前） | workflow.md 阶段 5—6：scripts/run_checks.py → language/zh.md §K 或 language/en.md → language/ai-tone.md 分级 | 终审报告：命中条目、次数、例句、改法、分级；作者回复后再改，改后复测 |
| 去 AI 味 | language/ai-tone.md → 对应语言文件 | 检测 → 分级报告 → 等回复 → 改写 → 复测 |
| 审稿意见修订规划 | sources/source-layer.md S1–S6 → 本协议第 5 节 | 任务清单（原子化、分类、依赖、执行块、冲突标注） |
| 风格学习（新对象） | sources/source-layer.md P7 → 盲测协议 | 语料清点 → 风格文件初版（含置信分级）→ 盲测验证；成品放 voices/ |
| 语料核对 | D9 → sources/corpus-evidence.md 的方法 | 统计结果写回 corpus-evidence.md，规则改动报本体系批准 |

## 4. 工作纪律（强制）

- **D1 批注默认**：未获本体系明确授权，一律只批注不代改（P5）。授权改稿的，按改稿路由执行，且作者裁决（如某条意见不采纳）立即结案、不再重提。
- **D2 事实来源纪律**：一切事实（数字、数据做法、出处、制度细节）必须来自当次任务的原稿、资料包或复现包原文；禁止凭记忆、印象或常识重构。引用语料例句必须逐字回读校验。拿不准的事实标"待核"，不写成定论。
- **D3 输入缺口主动询问协议（本体系2026-10-23 立规）**：开工前先盘点本任务的输入清单（原稿？事实包？数据口径？目标期刊与文体？作者已裁决事项？）。发现缺口时：①**只有用户能给的**（他的数据与数字、口径选择、价值裁决、未公开材料）——**主动向用户询问，集中一次问清，不许猜、不许编**；②可公开查证的——自己查证并注明来源；③暂时拿不到又不阻塞主体的——用明确的待补占位并在交付时列缺口清单。**三禁**：禁止编造数字或事实填空；禁止静默省略应有的论证功能位（缺材料就报告缺材料）；禁止用通用模板话冒充具体内容。交付报告必须包含：用了哪些输入、还缺什么、哪些是占位。
- **D4 在原稿上修**：已有成稿的任务以原稿为底增量修订；从零重写仅限真新稿且须基于用户给定的事实包。判例：2026-10-23 数据章演示——脱离原稿凭二手事实重写，产出全面劣于经导师组磨过的原稿（具体出处、1992 批次实例、逐 Panel 解读全丢），当场被作者否决。规则清单只能保下限，沉淀的具体度只在原稿里。
- **D5 数字纪律**：修订类交付前做数字多重集比对：估计数字零改动（有意改动逐项列明）；正文引用数字带基数锚（sections/results.md §6）；引言数字守配额且可信度数字单列不误扫（学者层 C2/C3）。
- **D6 校验与报告**：交付报告须含——做了什么、依据哪层哪条、校验方式与结果、未做或打折项及原因、待裁决项。失败与不确定性如实报告，不粉饰（判例：第三轮 lizhou 资料包截断、fan 生成日志截断，均已如实入档并修复流程）。
- **D7 文件维护**：规则文件的任何修改须经本体系批准（沿风格文件补丁流程：提案 → 批准 → 落盘 → 修订日志）；每次修改在对应文件加修订日志条目；本总纲随体系变更同步更新版本号。
- **D8 本地文件读写**：改用户本地 docx 前先从设备重新读取最新版本，写回时用修改时间守卫；写回前提醒作者先关闭该文件，避免 Word 用旧版本覆盖（判例 C-25）。作者自己改过的版本是底稿，不在旧版本上继续改。
- **D9 语料核对优先于经验规则**：对某条写作建议拿不准时，先到 Zotero 顶刊全文里统计核对（中文顶刊、英文顶刊分开），以语料为准；核不到的建议撤回或标"未核"。
- **D10 逐条设问裁决（本体系2026-11-11 立规）**：凡会改动稿件文字的发现（冒号、节号作主语、术语统一、交叉引用、长句拆分、删改段落、数字不一致等），**不许只报问题或只报数量**，必须逐条给出：①编号与位置；②原文整句；③问题与依据（文件 / 条号 / 判例）；④**拟改文**（可直接替换的完整句子；若建议保留，写"保留"并说明理由）。然后让作者逐条三选一：**同意 / 拒绝 / 自填改法**。执行方式：
  - 有提问工具（AskUserQuestion 等）时用提问工具：每题一条，题干含位置与问题，选项为"同意（推荐）"与"拒绝"，选项预览放"原文 → 拟改文"，作者自填走"其他"；每次最多 4 题，同类问题放同一批，按 P0 → P1 → P2 排序；超过 12 条时先问"同类 A 级是否一次性全部按建议"，作者选"逐条"再逐条问。
  - 无提问工具时：按 `templates/decisions.md` 编号列表，请作者按"1 同意　2 拒绝　3 改为：……"回复。
  - 无人应答时：只把清单写入 `work/decisions.md`，不改稿；交付报告列出待裁决条数。
  - 裁决结果逐条登记到 `work/decisions.md`（同意 / 拒绝 / 自填及最终文本），然后再落笔；拒绝过的同类改法，本稿内不再提。
  - 开放式问题也尽量做成设问：能给出选项的（写作模式、目标期刊、术语取名、两种结构方案取舍），就给 2–4 个选项并标推荐项，不让作者从空白开始回答。


## 5. 工作方法

- **范文对照**：每写一部分找 5—10 篇范文逐段拆开，标注每段在说什么、覆盖哪个维度，再对照自己的稿子查缺失维度；学的是段落功能分配，不是句式。【导师 A39】
- **修改次序与阶段**：先写中文捋顺逻辑；修改先实证后前端（先从数据章往后重过，实证定了再定引言与假设）；大块已完成就进入精雕细琢，不再动骨架。【导师 A40】
- **讨论成果清单化**：所有提出过的问题与处理方案汇成一张表持续维护，改稿逐项销账（现行形态：批注文件、修订说明、待裁决清单）。【导师 A41】
- **文献检索**：布置搜文献任务时显式要求覆盖各年代段，防止近十年断层。【导师 A42】
- **改稿次序**：先看逻辑，再改句子，最后改词汇。逻辑不通时改词句是白费；删掉全部逻辑连词通读一遍，标出缺推理的位置（见 structure.md §5.5）。【盲判记录】

## 6. 已知失效模式（F 清单，交付前自检）

- F1 漫画化：指纹词/招牌句式密度远超语料（实测可达 10–14 倍）→ 学者层指纹目标带。
- F2 招牌装置无据启用：无据"首次"、无真实双观点硬套 views 赛马 → 第零层事实门/适用门。
- F3 引文清零与定位段消失 → C1 引文义务、H1 定位段点名近亲。
- F4 篇幅单章塌陷：总比达标但单章缩到 0.3 倍以下 → v4 篇幅三层化、单章功能下限。
- F5 静默省略功能位：资料包未供给的论证功能（假说推导、命题合拢）被悄悄删节，路线图还照常宣称 → D3 第三禁＋文实对照检查。
- F6 归属层级错位：把本文论点写成学界共识（或反之）→ 高昊宇 G2 归属层级句。
- F7 凭记忆重构事实 → D2/D4（2026-10-23 新增，即数据章演示判例）。
- F8 控制变量与处理挂钩表述 → 导师层 A24 红线。
- F9 文献断层：AI 搜集文献只有最新＋经典、中间十年空白 → 导师层 A42；布置搜文献任务时必须显式要求覆盖各年代段。
- F10 降级对冲：把"表明"改成"指向""与……一致"（本体系2026-11-10 否决）→ language/zh.md §A。
- F11 解释性冒号与宣布式句子堆积 → language/zh.md §I、language/ai-tone.md Z2/Z9。
- F12 同一机制前后解释不一致（改一处未同步）→ language/zh.md §J、sources/casebook.md C-12。
- F13 重组段落时丢失主结果或数字 → sections/results.md §5、sources/casebook.md C-20。
- F16b 只报问题或数量、不给拟改文，或把多条改动打包让作者整体接受 → D10。
- F14 用经验规则改稿而未核对语料（如把前置定语、"当……时"当 AI 痕迹）→ D9、language/ai-tone.md §3。
- F15 写作模式错配：中文期刊稿用"我们"、英文目标稿结论写成分条政策建议等 → structure.md §0。
- F16 交叉引用编号失效：章节调整后括注、回指、路线图的节号未同步 → structure.md §5.4。
